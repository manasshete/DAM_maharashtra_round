Re:Learn — Technical Implementation & Trained Model Report

1. PROJECT OVERVIEW

Re:Learn is an AI-powered misconception-aware introductory programming tutor. It analyzes learner code, execution behavior, and reasoning to identify an underlying misconception rather than merely marking an answer wrong. It then provides a targeted intervention, reassesses the learner, and checks whether the misconception was actually resolved. The core diagnostic logic relies on deterministic execution traces and a trained statistical classifier, avoiding the unreliability of zero-shot LLM prompts for pedagogical evaluation.

3. TRAINED MISCONCEPTION MODEL

A. Model architecture
The system currently uses a NaiveBayesClassifier abstraction (lib/diagnosis/model/classifier.ts) built around the ml-naivebayes library as its baseline. It maps boolean/categorical feature vectors (e.g., ast_items_1, output_incorrect_second_element) to misconception classes (e.g., M02, RUNTIME_ERROR). In Phase 2D, we also experimentally fine-tuned microsoft/unixcoder-base to compare a semantic representation approach.

B. Training pipeline
1. Dataset: data/eval/development.jsonl (101 examples).
2. Feature Extraction: Deterministic rules in lib/evidence/extractor.ts pull properties from AST patterns, execution context, and reasoning into a FeatureVector.
3. Model Training: scripts/train-misconception-model.ts iterates over the development dataset.
4. Serialization: The resulting parameters are serialized to data/eval/misconception_model_v1.json.

C. Inference pipeline
1. New learner evidence: Student submits code. Pyodide captures execution traces (lib/execution/PyodideWorker.ts).
2. Feature vector: extractFeatures() generates the current feature set.
3. Trained model: The NaiveBayesClassifier instance receives the vector via model.predict(features).
4. Class probabilities: Returns a candidate class and a confidence score.
5. Candidate misconception: E.g., M02 with 0.85 confidence.

D. Evaluation pipeline
1. Held-out examples: scripts/evaluate-misconception-model.ts loads data/eval/held-out.jsonl (44 examples).
2. Loaded trained model: The script initializes the model using the saved artifact.
3. Predictions: Compares predicted class to ground-truth label.
4. Metrics: Generates Accuracy, Precision, Recall, and Macro-F1.

4. ACTUAL MODEL RESULTS

Evaluation on 44 Held-Out Examples

Baseline: Naive Bayes
Overall Accuracy: 61.36%
Macro-F1 Score: 0.4864

Experiment: UniXcoder (Phase 2D)
Overall Accuracy: 63.64%
Macro-F1 Score: 0.4268

Analysis:
While UniXcoder achieved perfect recall on core misconceptions (M01, M02, M03), it suffered from majority class collapse and failed to identify minority classes (OTHER_UNKNOWN, RUNTIME_ERROR), leading to a lower Macro-F1 score. The baseline Naive Bayes + Deterministic Guardrails remains the more balanced system for production use.

7. EVIDENCE ENGINE

The deterministic evidence extraction is defined in lib/evidence/extractor.ts.
The evidence hierarchy is:
- AST pattern -> Weak (e.g., items[1]).
- Execution behavior -> Moderate.
- Explicit reasoning -> Strong.

8. DIFFERENTIAL DIAGNOSIS

The engine (lib/diagnosis/differential.ts) is designed to prevent hallucination or over-confident guessing.

Flow:
trained model prediction + deterministic evidence + question context + guardrails -> DIAGNOSED / ABSTAIN

- Confidence Threshold: The model must predict a class with > 0.8 confidence.
- Abstention Behavior: If the candidate is M02 but the only evidence is ast_items_1 (weak evidence), the engine overrides the model and forces an ABSTAIN (Insufficient Evidence).

9. LLM / API ROLE

The LLM (managed via lib/ai/gateway.ts) is NOT the core misconception classifier.
Its role is restricted to translating the deterministic diagnosis into a friendly explanation and providing dynamic, context-aware feedback (e.g., structured explanations). It cannot invent misconception IDs or bypass the evidence engine.

10. M02

M02 = "The first list index is 1."
- Evidence: ast_items_1 (weak), output_incorrect_second_element (moderate), reasoning_index_1 (strong).
- Intervention: 4 levels (Hint, Explanation, Worked Example, Guided Practice).
- Direct Reassessment: "Print the first day of the week."
- Transfer Reassessment: "Print the first letter from the list ['a', 'b', 'c']."

11. CORRECT-ANSWER TRAP

The correct-answer trap (lib/learner/reassessment.ts) prevents premature graduation.
Important Case: Correct answer + incorrect/contradictory reasoning = misconception is NOT resolved.

12. INTERVENTION

The deterministic InterventionEngine (lib/intervention/engine.ts) escalates support levels based on repeated failures:
1. Hint
2. Explanation
3. Worked Example
4. Guided Practice

13. RESOLUTION

State transitions (lib/learner/resolution.ts):
INTERVENTION -> REASSESSMENT (direct) -> IMPROVING / PERSISTENT -> REASSESSMENT (transfer) + reasoning -> VERIFIED_RESOLVED

14. PYTHON EXECUTION

The deterministic execution sandbox (lib/execution/CodeVerifier.ts, lib/execution/PyodideWorker.ts, public/pyodide-worker.js) executes student code in an isolated browser thread using Pyodide (WASM).

19. MENTOR QUESTIONS

1. Should we retain Naive Bayes as the baseline and fine-tune a pretrained code model such as UniXcoder on the misconception dataset? (Answer: Phase 2D proved Naive Bayes is currently more balanced, but UniXcoder has potential with a larger dataset)
2. What dataset size/diversity would be sufficient for convincing held-out evaluation?
3. Should we expand from M02 into a small confusion set of closely related misconceptions?
4. Is our separation between the trained misconception model and LLM API appropriate?
5. What evaluation methodology would best demonstrate that the model generalizes to unseen learner responses?
